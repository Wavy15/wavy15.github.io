le cache poisonning (théorie)

1- trouver l'endpoint que l'on peut utiliser (souvent un répertoire important du type /account... avec un ficher ensuite (ex: https://0aa300cb034a7beb801303580057000d.web-security-academy.net/my-account/test_2.js)). Pour le trouver, il suffit dee trouver une requête qui va avoir un header avec X-... le grand X signifie que le cache a été atteint. 2- envoyer ensuite l'endpoint à la victime en changeant le body par exemple en mettant 3- rouvrir la requête via burp suite pour vérifier si les données ont changées et si oui, c'est terminé.
